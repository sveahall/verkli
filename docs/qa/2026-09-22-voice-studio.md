# V1 local voice studio implementation plan

Approved scope: NASTA-LEVERANSPLAN.md, package V1. Base 1b44b437; separate worktree. This implements a synthetic browser fixture only, with no upload, microphone, provider, database or production route changes.

Architecture: reusable VoiceSetupPanel consumes an injected VoiceSetupAdapter. A development-only fake adapter stores synthetic requests and a fake provider ledger in sessionStorage, scoped by demo author. This is not authorization or production persistence. Reload restores the same request and binding; an interrupted creation becomes uncertain and can only reconcile, never create again. Cleanup can be retried against the same immutable binding. UI key and response generation guard prevent old-owner responses being shown.

Files: lib/audiobook/voice-request-contract.ts defines validated sample/consent/request/binding snapshots and adapter types. app/dev/voice-setup/fixture-adapter.ts owns synthetic state/ledger/idempotency, with unit tests. features/audiobook/VoiceSetupPanel.tsx owns consent/sample/status/error actions. app/dev/voice-setup/page.tsx gates development; VoiceSetupFixture.tsx injects adapter and demo controls. scripts/qa-voice-setup.mjs verifies actual UI. No existing production voice files change.

## Manual QA (6 steps)

1. With existing dependencies and Node 22, run `npm run dev -w @verkli/web -- --hostname 127.0.0.1 --port 3248`. Open `http://127.0.0.1:3248/dev/voice-setup` in a fresh browser session. Confirm the empty state and the synthetic/browser-session notices. Real sample length, format and retention requirements remain undecided.
2. Leave consent unchecked and verify creation is disabled. Select missing and invalid samples and verify the explanation. Select the valid synthetic sample; focus the consent checkbox and press Space. Create a voice; verify Requesting then Ready and exactly one synthetic create. Reload and verify the same operation and recorded consent.
3. Revoke consent and verify Deleting then Deleted. Restart the simulated worker and verify no second delete. Use a fresh browser session for each following independent scenario, or run the automated script which resets only this fixture's sessionStorage key.
4. Choose Response lost, create and verify Uncertain without a second create action. Reconcile and verify the same operation becomes Ready. In another fresh session, revoke immediately after creating; verify the late success becomes Deleted without showing Ready.
5. Choose Cleanup fails, create and revoke; verify an explicit failure while deletion is pending. Reload, then Retry cleanup using the default successful worker; verify the original operation reaches Deleted. Switch demo author during a pending creation and verify the other author's empty state stays isolated.
6. At 390px verify no horizontal overflow. Run `npm run test -w @verkli/web -- src/lib/audiobook/voice-request-contract.test.ts src/app/dev/voice-setup/fixture-adapter.test.ts src/app/dev/voice-setup/page.test.tsx` and `node apps/web/scripts/qa-voice-setup.mjs` from repo root. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an existing Chromium binary if needed; no installation is required.
