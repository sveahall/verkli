# AI memory first release — Implementation Plan

> For agentic workers: use subagent-driven-development, with independent spec and quality review. User approved private memory tables; no new dependencies. Root Claude checkout is out of bounds.

**Goal:** Resume specialist conversations across reload/devices and share explicit, editable author/book/edition preferences.
**Architecture:** Four private Supabase tables; authenticated server loads and persists chat, never trusting client history for durable threads. Existing provider call remains; no extraction or summary calls in this release. Restored messages contain text only, not executable stale proposals.
**Tech Stack:** Existing Next.js, React, Zod, Supabase and Vitest; existing native PostgreSQL for RLS validation.

All API responses below use camelCase DTOs. Edition IDs nullable UUID; derive/check chapter edition in chat. A null edition is book-wide context and must not load edition-specific memories. Owner always comes from authenticated session.

```ts
type Memory = { id:string; content:string; scope:'author'|'book'|'edition'; updatedAt:string };
type SavedMessage = { id:string; role:'user'|'assistant'; content:string; createdAt:string };
type SavedThread = { id:string; title:string; updatedAt:string };
type Snapshot = { enabled:boolean; memories:Memory[] };
```

`GET /api/books/:id/ai/memory?editionId=` returns Snapshot. `POST` accepts `{operation:'save', id?:uuid, content, scope, editionId?:uuid|null}` or `{operation:'delete', id}` or `{operation:'settings', enabled:boolean}`. Each mutation returns refreshed Snapshot using supplied editionId; limits 500 chars/item, 24 applicable items, source is explicit user preference only. No model writes memories.

`GET /api/books/:id/ai/conversations?tool=&editionId=&threadId=` returns `{threads:SavedThread[], thread:SavedThread|null, messages:SavedMessage[]}`; omitted threadId resumes most recent matching scope. Last 50 turns displayed; last 12 provider context. `POST` accepts `{operation:'create', tool, editionId}` returns `{thread}` or `{operation:'delete',threadId}` returns `{deleted:true}`. Deletion is explicit UI action, not automatic on new conversation.

Chat adds `conversation:{threadId?:uuid,requestId:uuid,editionId?:uuid|null,temporary:boolean}`. Durable mode validates scoped thread (create if absent), reserves request before provider, reads stored history and enabled preferences, then persists validated reply. Response adds `threadId`, `persistence:'saved'|'temporary'|'failed'` and uses stable reply id. Repeated requestId cannot execute another provider call; in-progress returns 409, finished replays saved text without executable proposals. Save failure never claims saved. Temporary mode reads/writes no memory or thread rows; existing limited client history is allowed there. No implicit history import from old in-memory UI.
